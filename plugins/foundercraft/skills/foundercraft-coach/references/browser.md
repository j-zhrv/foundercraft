# Подключение к вкладке FounderCraft

Читай при первом подключении через `cua_repl` или восстановлении после технического сбоя. При обычном продолжении используй уже прочитанную документацию и доступные привязки. Этот справочник описывает клиент хоста; он не задаёт семантику команд сайта.

Не делай скриншоты и не добавляй изображения экрана в контекст плагина, в том числе после открытия вкладки, действия или при восстановлении. Для подключения используй сведения о вкладках и регистрации WebMCP; для продолжения — данные ответа инструмента. Не вызывай обзор DOM или визуальную проверку как ритуал подтверждения. Если инструмент недоступен, сообщи ограничение без снимков.

## Codex с cua_repl

Первый вызов после инициализации или сброса содержит ровно одну документированную операцию выбора встроенного браузера, без снимков и дополнительных действий:

```javascript
const browser = await cua.getBrowser({ id: "iab" });
```

Прочти возвращённую документацию. Затем получи только его вкладки через `cua.listTabs({ browser: browser.browserId })` или другой указанный документацией метод. Выбирай указанную или подходящую вкладку на точном домене `foundercraft.ai-era.ru`, учитывая выбор пользователя. SEO-страницы могут регистрировать `foundercraft_site_*`, `/app/` регистрирует инструменты карты и сессии. Проверяй реальные регистрации; чтение справочника не заменяет вызовов приложения. Не закрепляй числовые ID.

При получении существующей вкладки укажи тот же браузер:

```javascript
const tab = await cua.getTab(tabId, { browser: browser.browserId });
```

Если подходящей вкладки сайта нет, для первого или неизвестного входа открой `https://foundercraft.ai-era.ru/` через `cua.createBrowserTab` в том же браузере. Только для явного продолжения ранее начатой сессии открывай `/app/` без параметров и дождись восстановления. При создании предпочитай видимую пользователю вкладку в том же выбранном `iab`: если текущая документация хоста описывает параметр видимости, используй его документированное значение. Не переносись в другой браузер и не добавляй неподдерживаемые параметры. До урока учитывай доступное подтверждение показа; если хост его не даёт, не утверждай, что страница уже видна, и кратко помоги пользователю открыть существующую вкладку. Первый путь в обучение идёт через вводную или ситуационную статью и оффер по `voice-entry.md`. Не объявляй навигацию прочтением человеком или согласием на старт. После загрузки страницы обнаружь её инструменты:

```javascript
const webmcp = await tab.capabilities.get("webmcp");
let tools = await webmcp.fetchTools();
```

Если актуальное уведомление для этого документа уже содержит имена и схемы инструментов, используй его. Иначе один раз выведи `nodeRepl.write(tools.description())`. Не выводи повторно то же описание только ради подтверждения; перед новым сообщением всё равно заново выполняй `fetchTools()`, как требует контракт хоста.

Для структурированного вызова используй полное имя из текущего описания:

```javascript
const raw = await tools.call(registeredName, args);
const result = typeof raw === "string" ? JSON.parse(raw) : raw;
nodeRepl.write(result);
```

`tabId`, `registeredName` и `args` берутся из обнаруженных вкладок, схем и готовых вызовов. Пример не является готовым вызовом с фиксированными идентификаторами. Разбери строковый JSON до обращения к `result.data.revision` или `result.stateVersion`. Старое Markdown-досье не выдавай за JSON; для карточки выбирай `format=json` по схеме. Перед первым WebMCP-вызовом каждого нового сообщения заново выполни `fetchTools()`. После навигации заново получи capability WebMCP у той же вкладки и регистрации нового документа. При устаревшем handle обнови их, не повторяя навигацию. Существующую привязку к браузеру сохраняй. Если исход мутации неизвестен, сначала прочти состояние, а не повторяй действие.

## Видимость уже открытой вкладки

Привязка `getTab` и успешный WebMCP-вызов не доказывают, что пользователь видит вкладку. При «не вижу браузер/страницу» сохрани выбранный `tabId`: используй только документированную текущим хостом возможность показать или активировать эту же вкладку, если она доступна. Не выдумывай метод focus/show, не создавай пустую вкладку или дубликат сайта ради показа и не перезагружай существующую. Если такой возможности в документации нет, честно назови ограничение и попроси открыть уже существующую вкладку средствами хоста; не объявляй её фоновой без подтверждения. Успех выбора вкладки не равен подтверждённой видимости у человека. Этот запрос не разрешает начать/перезапустить обучение или менять его фокус.

После прерывания подключения сначала проверь доступные вкладки и актуальные регистрации: не повторяй `createBrowserTab`, если вкладка уже создана. При нескольких кандидатах без подтверждённого выбора уточни нужную; не выбирай по догадке. Восстанавливай доступ к существующему состоянию, а не создавай новое.

## ChatGPT и другие поддерживаемые хосты

Используй документированный WebMCP-клиент текущей вкладки браузера рядом с чатом. Не переносись в личный Chrome при отсутствии привычного Codex API. Открытие интерфейса сайта само по себе не доказывает, что хост доставляет инструменты.

При сбое проверь загрузку приложения, клиент вкладки и доступность capability/регистраций. Не создавай HTTP MCP-сервер и не вызывай скрытые функции страницы произвольным JavaScript. Если доступ подтвердить нельзя, сообщи конкретное ограничение. Отсутствие активного дела при работающем WebMCP — другой случай, описанный в основном скилле.

## Переход с SEO в приложение

Для чтения текущей главной/статьи/оффера используй `foundercraft_site_read_page` и его продолжения, для выбора — `foundercraft_site_find_situations` / `foundercraft_site_find_builds`. `foundercraft_site_open` принимает target article/offer/app и ID из каталога; фиксированные target home/intro/map_article открывают главную, вводную статью и статью о карте дел без id; expectedRevision бери из read_page. Его navigationScheduled подтверждает только поставленный переход, не прибытие, прочтение или старт сессии. После перехода заново обнаружь инструменты.

Для нового выбора пройди вводную или ситуационную статью и оффер. Если пользователь уже перенёс конкретный `/start/?mode=teacher`, не отправляй его на главную заново: используй выбранную страницу по `site-handoff.md`. Её `nextActions.prepareLearning` описывает семантический переход подготовки; проверяй его наличие и текущую регистрацию. Старый `site_open(target=app)` может открыть только описание: это не отказ `start_learning`. После перехода получи свежий контекст приложения и используй старт после согласия; если подготовка открыта, подтвердить её можно через `confirmPreparation=true`. Не добавляй параметры вручную и не обходи вход скрытым JavaScript. Не повторяй мутацию ради восстановления ответа.
